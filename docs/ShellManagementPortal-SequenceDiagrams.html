Shell Management Portal — Sequence Diagrams

Parent portal: Blazor Server web, ASP.NET Core API, WSO2 Identity Server, SQL Server (SMPortal).

Overview 1. Login 2. Shell load 3. Local CQRS 4. Users / SCIM 5. Logout

1. OIDC login (authorization code)

Unauthenticated requests are challenged. Web is an OIDC confidential client; the session is a cookie and the access token is saved for API calls.

sequenceDiagram
    autonumber
    actor Admin
    participant Web as ShellMgmt.Web (Blazor :7067)
    participant WSO2 as WSO2 Identity Server
    participant API as ShellMgmt.Api (:7203)
    participant SQL as SQL Server (SMPortal)

    Admin->>Web: GET /Account/Login
    Web-->>Admin: OIDC Challenge (302)
    Admin->>WSO2: GET /oauth2/authorize (code + scopes)
    WSO2-->>Admin: Login UI
    Admin->>WSO2: Credentials
    WSO2-->>Admin: 302 /signin-oidc?code=
    Admin->>Web: GET /signin-oidc
    Web->>WSO2: POST /oauth2/token (code + client secret)
    WSO2-->>Web: access_token, id_token, refresh_token
    Web->>WSO2: GET UserInfo
    WSO2-->>Web: Claims (sub, name, groups, roles)
    Note over Web: Cookie session + SaveTokens. OnTokenValidated fires.
    Web->>API: POST userlog/create (Login Success)
    API->>SQL: Insert Userlog
    SQL-->>API: OK
    API-->>Web: 200
    Web-->>Admin: Redirect / (authenticated cookie)

2. Parent shell bootstrap

MainLayout reads the OIDC access token from the cookie, then loads profile, child apps, tenant, and sidebar menus. Non-admin users are filtered through UserMenuAssignment.

sequenceDiagram
    autonumber
    actor Admin
    participant Web as ShellMgmt.Web
    participant WSO2 as WSO2 IS
    participant API as ShellMgmt.Api
    participant SQL as SQL Server

    Admin->>Web: Open portal (authenticated cookie)
    Note over Web: GetTokenAsync(access_token) to AppConfig.AccessToken

    Web->>API: GET user/Get/{sub} Bearer JWT
    API->>WSO2: Validate JWT (issuer / JWKS)
    WSO2-->>API: Token valid
    API->>WSO2: SCIM GET /Users/{sub} (Basic admin)
    WSO2-->>API: User profile
    API-->>Web: UserDto (display name, SCIM username)

    Web->>API: GET appgroup/GetUserApps/{sub}
    API->>WSO2: SCIM user groups
    API->>SQL: AppGroupAssignment intersect groups
    SQL-->>API: Assigned child apps
    API-->>Web: Child apps for sidebar

    Web->>API: GET menuitem/get
    API->>SQL: MediatR GetMenuItemQuery via ReadDbContext
    SQL-->>API: Menu items
    API-->>Web: All menu items

    Web->>API: GET usermenu/GetAllMappings
    API->>SQL: UserMenuAssignment
    SQL-->>API: Mappings
    API-->>Web: Assignments
    Note over Web: Admin shows all menus. Else filter by sub or SCIM username plus parents.
    Web-->>Admin: Sidebar + child-app launchers

3. Local config write (CQRS)

Menus, claims, institutions, org units, apps, and tenants live in SQL Server. Controllers send MediatR commands; AuditLogFilter writes a Userlog after the action.

sequenceDiagram
    autonumber
    actor Admin
    participant Web as ShellMgmt.Web
    participant WSO2 as WSO2 IS
    participant API as ShellMgmt.Api
    participant SQL as SQL Server

    Admin->>Web: Save MenuItem / Claim / App form
    Web->>API: PUT api/v1/menuitem/Update Bearer JWT
    API->>WSO2: JWT Bearer validation
    WSO2-->>API: OK
    Note over API: UpdateMenuItemCommand to handler
    API->>SQL: AppDbContext write + Unit of Work
    SQL-->>API: Persisted entity
    Note over API: AuditLogFilter sends CreateUserlogCommand
    API->>SQL: Insert Userlog
    API-->>Web: 200 + DTO
    Web-->>Admin: List / form refresh

4. Users and groups (SCIM 2.0)

Identity is not stored in SMPortal. UserController and GroupController call ScimService with WSO2 admin Basic auth. The portal JWT only authorizes the admin calling the API.

sequenceDiagram
    autonumber
    actor Admin
    participant Web as ShellMgmt.Web
    participant WSO2 as WSO2 IS
    participant API as ShellMgmt.Api
    participant SQL as SQL Server

    Admin->>Web: Users / Groups page (create or list)
    Web->>API: POST api/v1/user/Create Bearer JWT
    API->>WSO2: Validate caller JWT
    WSO2-->>API: OK
    API->>WSO2: SCIM POST /Users (Basic admin)
    WSO2-->>API: Created SCIM user
    API->>SQL: Audit Userlog only (no user row)
    API-->>Web: UserDto
    Web-->>Admin: User created
    Note over Web,WSO2: Optional Web Wso2Service uses password grant and SCIM Roles for permissions.

5. Logout

Account/Logout writes an audit row, then signs out the cookie scheme and the OpenIdConnect scheme.

sequenceDiagram
    autonumber
    actor Admin
    participant Web as ShellMgmt.Web
    participant API as ShellMgmt.Api
    participant SQL as SQL Server

    Admin->>Web: GET /Account/Logout
    Web->>API: POST userlog/create (Logout Success)
    API->>SQL: Insert Userlog
    Note over Web: SignOut cookie + OpenIdConnect. Cookie deleted.
    Web-->>Admin: LocalRedirect / (next hit challenges login)
